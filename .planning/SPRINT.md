Notes: 7 — `src/utils/rollBounds.ts` (+ test) reads the wall numbers straight from RollingArea (exported `WALL_THICKNESS`); "inside" = the walls' inside faces, a die high in the air still counts as inside. Test failed (no module) before the helper existed, 9/9 after. New `content/tuning/physics.json` (outOfBoundsMargin 0.25, maxReleaseSpeed). 8 — escape/hang causes found by `npm run e2e:physics` (new, scripted rolls with 6 gestures, checks every die every frame): (a) **the hang**: settle checks ran *during* the gather, so a just-spawned pool sitting still "settled" mid-gather, results were ignored (phase gathering), `hasFired` stayed true → phase stuck in `rolling` forever, 10 s timeout couldn't fire (seen 2–3× per 30 rolls before). Now nothing can settle while gathering; the roll's clock starts at release. (b) a tap that starts+ends between two drawn frames was never seen by DicePool (it watched React state) → same forever-hang; release is now a direct call (`releaseGather`, from pointer-up / auto-release / AFK) and DicePool reads the store in useFrame. (c) **dice flying out**: the attractor set velocity once per drawn frame, but after a slow frame Rapier runs several fixed steps with it → overshoot, and gathering dice are sensors so they sailed through walls (seen at x 12.3, z 7). Attractor now runs per physics step (`useBeforePhysicsStep`). (d) Dead fling fixed: DicePool keeps its own orbit centre (`getGatherCenter`, clamped like the ring); horizontal release speed capped at `maxReleaseSpeed` 20 (the fling tops out ~19–20 u/s anyway; the old leftover attractor velocity could be 40). Safety net: any die past a wall / below the floor is put back (dev log `[PhysicsDie] out of bounds`). After: 50 rolls, 0 hangs, 0 timeouts. Open: freshly spawned dice sometimes sink through the floor while being pulled (velocity is set upward but the body moves down) — net catches it; chased in task 9. 9 — per-die `[Gather]` log (dev only, DicePool; quick taps under 0.6 s aren't judged). **B008 cause**: every die had 23 colliders, not 1 — the RigidBody auto-built colliders from the die mesh + all 21 pip meshes on top of our cube, and every `setHalfExtents` loop (gather shrink / release grow) blew the pip ones up to full die size, sitting on the faces. Lumpy compound: dice rested at y≈0.8 instead of 0.4 after a gather, and freshly spawned dice sometimes sank through the floor while the pull set them rising (logged: velocity +7…+22 up, body going down) = "flickers/scales as if grabbed, then drops back". Fix: `colliders={false}` + cube `density={2}` (mass stays 1.024, so impulses feel the same). Not caused by escaped dice. Before: ~9 gathering put-backs + dice missed in 50 rolls; after: 50 rolls, 0 missed, 0 hangs, 0 timeouts; 1 released die was caught pushed into the left wall and put back by the net (fast die + collider growing back at the wall). May also be behind B001/B002 (canted dice) — watch. Final check, 3 × `npm run e2e:physics` (50 rolls each): 0 hangs, 0 10 s timeouts every run; gathers with a missed die 0 / 1 / 0 (the 1 wasn't captured — rerun if it shows up again); 0–1 released dice per run pushed into the LEFT wall and put back by the net (x≈0.45–0.49). Feel-check on a real device: release fling is live again (it was dead since v1.5) and capped at 20. Follow-up (main's leftover miss: `tap`, pool 1, "0.72 s", die didn't move at all): dev-logged every attract on/off + first pull steps and counted physics time per gather. The attractor WAS armed (target set, start distance recorded, body present); simply zero physics steps ran between gather start and release — this headless software-GPU browser runs at ~3–6 fps (frames of 150–480 ms measured before AND after taps, so not a gather-start spike), and a 150 ms tap can end before the next frame steps the world. Log now judges by physics seconds of pull (`0.81s held, 0.00s of pull` → too short to judge); e2e asserts every gather with ≥ 0.6 s of pull swept every die. Not a stale ref / unarmed attractor. Side note for Muzzy (not changed): on release every die is snapped to its ring spot, so on a very slow phone frame a quick tap would pop dice up to ring height before they fall — feel-check. e2e exit code: `run()` already exits 1 on FAIL (checked `npm run e2e:physics` → exit 1); the 0 seen was a pipe's exit code.
