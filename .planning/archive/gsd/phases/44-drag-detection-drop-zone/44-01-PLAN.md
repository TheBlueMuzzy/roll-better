- `cancelDragUnlock()` — resets to inactive (for snap-back, used in 44-02)

  <name>Task 2: Replace UnlockableDie onClick with drag pointer events</name>
  <files>src/components/PlayerRow.tsx</files>
  <action>
Replace the onClick handler on UnlockableDie with onPointerDown/Move/Up for drag behavior.

**onPointerDown:**
- e.stopPropagation()
- If not selectable (can't unlock), return early
- Use ray-plane intersection pattern from RollingArea.tsx: create a static Plane at Y = DIE_SIZE/2 (table level, not ORBIT_HEIGHT — die drags along table plane)
- Capture the die's slot position as originPosition
- Call startDragUnlock(slotIndex, value, originPosition)
- Set a local ref `isDragging = true`

**onPointerMove:**
- If not isDragging, return
- e.stopPropagation()
- Ray-plane intersect to get world position
- Call updateDragPosition([x, DIE_SIZE/2, z])

**onPointerUp:**
- If not isDragging, return
- e.stopPropagation()
- Set isDragging = false
- For now (before 44-02): just call cancelDragUnlock() to snap back. Phase 44-02 adds drop zone detection here.

**Visual: die follows pointer during drag:**
- In the useFrame hook, when dragUnlockState.active && dragUnlockState.slotIndex === slotIndex:
  - Override the die's position to dragUnlockState.currentPosition (instead of slot position)
  - Lift die slightly higher than normal (e.g., DIE_SIZE * 0.75 for Y) so it looks "picked up"
  - Skip pulse animation while dragging

**Important:** Keep the existing lift/pulse/shake animations for non-dragging state. Only override position when THIS die is being dragged. Use `useGameStore(s => s.dragUnlockState)` selector.

**Pointer capture:** Add `onPointerDown` handler that calls `(e.target as Element).setPointerCapture?.(e.pointerId)` to ensure Move/Up events continue even if pointer leaves the mesh. Release on pointerUp.

Do NOT use window-level event listeners — R3F pointer events with capture handle this cleanly.
