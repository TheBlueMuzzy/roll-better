**Rolling zone boundaries (from RollingArea.tsx):**
- X: 0.5 to 9.5 (ROLLING_X_OFFSET ± ARENA_HALF_X)
- Z: -5 to 5 (ROLLING_Z_MIN to ROLLING_Z_MAX)
- These define where a die drop is "valid" (inside rolling area)

**Lock zone (player row area):**
- Player row at z = -3.75, slots at ROW_X_OFFSET = -3.5
- Anything on the left side / player row area is "lock zone"

Create a utility `src/utils/dropZone.ts`:
```
isInRollingZone(position: [number, number, number]): boolean
```
Returns true if position is inside the rolling area bounds. Use the constants from RollingArea.tsx (import them, or define shared constants if they're not already exported). Add some padding/tolerance (e.g., 0.5 units inside each edge) so dice don't land right on the wall.

In UnlockableDie's onPointerUp handler (from 44-01):
- Get the final drag position from dragUnlockState.currentPosition
- If `isInRollingZone(currentPosition)`:
  - For now, call `cancelDragUnlock()` (Phase 45 will replace this with `completeDragUnlock` + commit logic)
  - Log "VALID DROP" to console so we can verify detection works
- If NOT in rolling zone:
  - Call `cancelDragUnlock()` — die needs to animate back

Also handle the edge case: if onPointerUp fires but currentPosition is null (pointer barely moved), treat as invalid drop.

<task type="auto">
  <name>Task 2: Snap-back animation on invalid drop</name>
  <files>src/components/PlayerRow.tsx</files>
  <action>
When cancelDragUnlock() is called (invalid drop or phase ended), the die should smoothly lerp back to its original slot position instead of teleporting.

In UnlockableDie's useFrame:
- Add a "returning" state: when dragUnlockState is no longer active AND the die was just being dragged (track via a local ref `wasDragging`):
  - Store the last drag position in a local ref
  - Lerp from that position back to the slot position over ~0.2 seconds using the same lerp pattern as the existing lift animation: `pos += (target - pos) * Math.min(1, delta * 12)`
  - Apply to both X and Z (Y returns to DIE_SIZE/2 + any lift)
  - Once close enough to slot (distance < 0.01), snap to exact position and clear the returning state

Keep it simple — no spring physics, just a smooth lerp like the existing lift. The returning animation should feel quick and snappy (the `* 12` speed factor matches the existing lift lerp speed).
  </action>
  <verify>TypeScript compiles. During unlock phase: drag a die outside rolling zone, release — die smoothly returns to slot. No teleporting.</verify>
  <done>Invalid drops animate back to slot smoothly. No visual glitches during return. Return animation is quick (~0.2s).</done>
