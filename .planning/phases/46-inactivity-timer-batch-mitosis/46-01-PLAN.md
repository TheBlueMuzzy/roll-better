The existing RollingCountdown component already handles timer UI (countdown bar, onTimeout callback). It takes `active: boolean` and `onTimeout: () => void`. But it uses a fixed 20s `TIMEOUT_MS`.

Two approaches:
**A)** Modify RollingCountdown to accept a configurable `duration` prop and a `resetKey` prop (number that increments on each reset, triggering useEffect re-initialization).
**B)** Create new state in the store to track the timer.

Go with **A** — it's simpler. The timer is purely UI-driven (client-side), matching the existing pattern.

**In gameStore:** Add a `unlockTimerResetKey: number` to state (top-level). Each time `completeDragUnlock()` succeeds (after the commit logic), increment this key: `set({ unlockTimerResetKey: state.unlockTimerResetKey + 1 })`. Initialize to 0.

This gives the UI component a signal to restart its countdown on each drag action.

**In completeDragUnlock():** After the existing commit logic (add to committedUnlocks, remove from lockedDice), add:
```typescript

```
to the `set()` call.

Also add `resetUnlockTimerKey: () => set({ unlockTimerResetKey: 0 })` for cleanup.

**Modify RollingCountdown.tsx:**

Add new optional props:
```typescript
interface RollingCountdownProps {
  active: boolean;
  onTimeout: () => void;
  duration?: number;   // Override TIMEOUT_MS (in ms). Default: 20000
  resetKey?: number;   // When this changes, restart the timer
}
```

- Use `duration ?? 20_000` instead of hardcoded `TIMEOUT_MS` for the countdown calculation
- Add a `useEffect` that watches `resetKey`: when it changes AND active is true, restart the timer (reset `startRef.current = Date.now()`, reset `firedRef.current = false`, reset `fraction` to 1)
- Keep backward compatibility — existing callers that don't pass duration/resetKey still work with 20s default

**In HUD.tsx:**

Find where RollingCountdown is rendered for the unlock phase (line ~79):

```typescript
const showUnlockCountdown = isOnlineGame && phase === 'unlocking' && !hasSubmittedUnlock && !animationsInProgress;
```

Change this to show the inactivity timer for ALL unlock phases (not just online):
```typescript
const showUnlockCountdown = phase === 'unlocking' && !animationsInProgress;
```

Remove the `isOnlineGame` guard — the inactivity timer applies to both offline and online games now.

Pass the new props:

The duration logic: first activation (resetKey=0) uses 4s, subsequent resets (resetKey>0) use 3s.
